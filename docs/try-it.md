# 一分钟演示与首次安装验收

> **开始前先读这条**：守卫命中会**立即中止当前生成**，而且**没有"仅提示"或"关闭守卫"的模式** ——
> 它误判了你的正常推理时，你没有开关可以降级（只能改配置或卸载）。
> 2026-10-01 本机的第一条真实命中即是一次**误报**：模型在正常地写"连按 N 次同一按键"的命令，
> 同一个按键码被连续写出十几次，被 `repeat-inline` 当成周期复读。
> 形态说明见 [README 的已知边界](../README.md)（**只描述形态**：命中片段属私人任务内容，
> 具体命令与思考原文不进公开仓库），最小合成复现见仓库 `work/guard-repro-inline-cmd.mjs`
> （开发用探针，不随 npm 包发布）。第 4 节有完整的守卫与隐私边界。

## 1. 一分钟演示

准备 Node ≥22.19，并在公开仓库的副本中安装依赖：

```bash
git clone https://github.com/donghangxunlang-cmd/dsh-attention-health.git
cd dsh-attention-health
npm install --no-audit --no-fund
node tools/demo.mjs
```

下载与安装依赖需要联网；完成准备后，演示本身离线运行，无需 DSH、模型凭据或真实会话。
演示工具随 GitHub 源码提供，不包含在 npm 插件包内。

演示会调用当前源码的 host 注册、思考守卫、投影和交接路由，依次检查：

| 输入 | 应看到的结果 |
| --- | --- |
| 三行不同的合成思考 | 不调用取消接口，不写命中记录 |
| 同一条合成思考连续重复 | 第 8 行命中，取消接口恰好调用 1 次 |
| 声明窗口占用 50%，模拟宿主记录中止事件 | 建议机械交接，文档包含任务、进度和待办 |
| 相同复读，设置 `GUARD_TAIL=0` | 仍会中止；保留首尾各 40 字以及命中样本 |
| 请求交接文档 | 使用 `record=0`，不写交接历史 |

所有本地读写隔离在自动创建的临时 `DSH_HOME`，正常结束或捕获错误时清理。
脚本会临时覆盖当前进程的留存配置，让两种情况都可重现；不修改系统环境变量。
任一断言失败即返回非零退出码，CI 也运行这条命令。

要查看完整合成文档和两种守卫记录：

```bash
node tools/demo.mjs --out ./demo-result
```

目标目录须不存在，父目录须存在。产物为 `HANDOFF.md`、`guard-default.json`、
`guard-reduced.json` 和 `summary.json`，全部源于虚构内容，可用于介绍插件。
判定输入固定；生成时间、记录时间、耗时和按当前价格档位展示的金额会随运行变化。
所有 token 与金额只用于合成演示，不代表真实用量或账单。

**验证范围**：演示使用模拟宿主接收取消请求；它没有启动 DSH，也没有中止真实模型生成。
因此还需要下面的安装验收来确认 DSH 加载和浏览器交互。合成样本通过也不能证明跨用户误报率。

## 2. 在自己的 DSH 上验收

先记录操作系统、Node / DSH / pnpm 版本和插件版本；命令在运行 DSH 的同一环境中执行。
版本号即可，不需要用户名、机器名、会话 ID 或安装绝对路径。

1. 按 README 安装：`dsh plugin --profile web add -w dsh-attention-health`。
   pnpm 主版本要与 profile 一致。记录安装来源（npm、GitHub 或脱敏 tgz）及实际安装版本。
2. 重启 DSH，刷新浏览器，在一个可公开的简短测试会话中确认能看到「复制交接内容」入口。
   健康会话可能只有淡字入口，不一定出现彩色警告条。
3. 用自己的普通任务观察是否发生不应有的中止。无需为验收特意让模型生成复读，
   也无需把私人任务内容发给维护者。
4. 点「复制交接内容」，先粘贴到本地文本编辑器，确认包含自己的请求和进度；
   自行检查后再粘到新会话。记录复制是否成功、内容是否足以接手。
5. 若测试更少留存，将 `DSH_ATTENTION_HEALTH_GUARD_TAIL=0` 设置到 **DSH 启动进程的环境**，
   再重启 DSH。刷新网页不会改变 host 环境。此设置只减少命中记录的尾部字段，
   不会关闭守卫或清除已有记录，也不会脱敏交接文档。

## 3. 安全反馈

通过 [Issue 入口](https://github.com/donghangxunlang-cmd/dsh-attention-health/issues/new/choose)
选择「安装与交接体验」或「守卫误报 / 漏报」。成功安装的报告也有价值，
尤其是另一台机器、另一种系统或模型；请区分真实 DSH 使用与合成演示。

建议反馈：版本、安装来源、重现步骤、预期与实际结果、守卫命中类型、是否在重复引用或代码。
误报先写结构描述，例如「正常解释中重复引用同一行」，能重现时再附合成最小样本。
没有足够信息时，维护者应标记“无法判断”，不把所有命中都记作正确拦截。

**不要直接上传**完整日志、交接文档、`guard-trips.jsonl`、带访问 token 的页面地址，
或包含私人任务的截图。`TAIL=0` 记录仍含原文片段，需逐项人工检查。
插件没有遥测，以上反馈只会由你主动提交。

## 4. 当前守卫与隐私边界

- 守卫命中会中止当前生成；当前没有对用户开放的“仅提示”或“关闭守卫”模式。
- `GUARD_TAIL=0` 是减少留存，不是守卫模式或零原文模式。
- 交接文档是机械提炼，不是自动脱敏；精简版也可能包含完整请求、代码和路径。
- 修改留存环境变量不影响 DSH 自己的会话日志。详细字段见 [隐私说明](privacy.md)。
